# role_collecteur.md — Collector (`2_collecteur/`)

External participant who collects samples from across Tunisia.

---

## CRITICAL — Sample identity: two separate identifiers

**A sample IS a bottle. One bottle = one `Echantillon`. Every sample has two identifiers that must never be confused:**

| Layer | Field name | JSON key | Meaning |
|-------|-----------|----------|---------|
| Django | `Echantillon.numero` | `"numero"` | Auto-generated app sequence: `YYYY/NNNN` (e.g. `"2025/0003"`) — never typed by the collector |
| Django | `Echantillon.reference_bouteille` | `"reference_bouteille"` | Physical label the collector writes on the bottle (e.g. `"CHEMLALI-C1"`) |
| Flutter | `EchantillonCollecteur.numero` | reads `"numero"` | Read-only — assigned on creation, never sent in create/update payload |
| Flutter | `EchantillonCollecteur.referenceBouteille` | reads/writes `"reference_bouteille"` | Required field in the creation form |

**Rules:**
- `numero` is generated by the app on creation (`{year}/{counter.padLeft(4,'0')}`). Never ask the collector to type it.
- `reference_bouteille` is what the collector writes on the physical label. It is required and editable.
- In Flutter `fromJson()`: `referenceBouteille: json['reference_bouteille']`.
- In Flutter `toJson()`: `'reference_bouteille': referenceBouteille`.
- The sample also has a UUID `id` (primary key) — that is separate from both. All three exist simultaneously.

## Pages

- **Échantillons** — own registered samples, filterable by date. Shows current state per sample (see states below).
- **Ajouter un échantillon** (FAB) — form: supplier code, origin (gouvernorat/délégation), référence bouteille, variety, quantity, numéro de citerne, optional expected arrival date. Collector can photo the handwritten bottle label → Azure AI Document Intelligence custom model extracts the structured fields → collector reviews and corrects before saving. Multiple bottles → each bottle gets its own `reference_bouteille` and is saved as a separate `Echantillon` record. The `numero` is auto-assigned on save.
- **Carte** — map of Tunisian delegations. Visited delegations highlighted, unvisited not. Helps plan future routes.
- **Chat** — messaging with Direction (CEO). Planned; implement if time allows.
- **Dashboard** — collector-level KPIs and activity summary.
- **Profile** — edit name, phone, email, password, photo.

**Cannot see taster evaluations.**

## Sample States (collector view)

| State | Edit | Delete | Notes |
|-------|------|--------|-------|
| `Réceptionné` | All fields | ✅ Yes | Not yet physically at company |
| `Réceptionné (reçu physiquement)` | Limited fields only | ❌ No | Taster confirmed physical arrival. **Edits are tracked** — previous value visible to all actors |
| `En négociation` | — | ❌ No | CEO approved for purchase. CEO's `budgetNegociation` (DT/kg, with the derived DT/tonne) + `dateLivraisonStockSouhaitee` shown in collapsible section. The collector closes the negotiation himself: **Confirmer l'achat** or **Achat non conclu**. No CEO validation step. |
| `Achat confirmé` | price, tank, delivery date, remark | ❌ No | Collector confirmed purchase with `prixFinal` (DT/kg), `numCiterne`, stock delivery date (`date_livraison_stock`, optional `_fin`), `remarqueCollecteur`. The CEO is notified. |
| `Achat non conclu` | — | ❌ No | Negotiation failed. Optional reason in `raison_non_conclu` (separate from the CEO's `raison_refus`). The CEO is notified and can reopen the negotiation. |

## State Transitions (collector-relevant)

| Transition | Who | Fields set |
|---|---|---|
| Register → Réceptionné | Collector or Taster | All sample fields, optionally `dateArriveeEchantillon` |
| Réceptionné → recuPhysiquement | Taster | `recuPhysiquement = true`, `dateReceptionEchantillon` |
| Réceptionné → En négociation | CEO | `budgetNegociation`, `dateLivraisonStockSouhaitee` |
| En négociation → Achat confirmé | Collector (`confirmer-achat`) | `prixFinal`, `numCiterne`, `date_livraison_stock(_fin)`, `remarqueCollecteur` |
| En négociation → Achat non conclu | Collector (`non-conclu`) | `raison_non_conclu` (optional) |
| Achat non conclu → En négociation | CEO (`approuver`) | new `budgetNegociation`; `nb_renegociations` +1 |
| Achat confirmé → Stock reçu | CEO or Collector | `dateArriveeStock` |

---

## Edit History Rule

Once `recuPhysiquement = true`, any field edit must store the previous value in `editHistory` (list on the model). All actors (CEO, taster, lab) see old value + new value, clearly labelled — like the "edited" indicator in messaging apps.

---

## Offline Mode (critical — do not break)

- All writes queued locally (using `sqflite` or `hive`) when offline.
- Sync runs when connection is restored, calling the same service methods that will hit the Django API.
- Sync logic lives in `CollecteurSyncService` — never in widgets.
- Queue entries: `synced: false` flag + local-only UUID. Server assigns canonical UUID on sync; local record must be updated.
